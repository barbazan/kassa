# Оплата VK в kassa

Клиентский сервис `VKBillingService` реализует общий `BillingService`, наследуется от `BaseBillingService` и выдаёт товары через существующий `PurchaseListener`. Поддерживается текущий товар `full_version` из `BillingCatalog`. Отдельного товара отключения рекламы в каталоге сейчас нет.

## Подключение

При запуске игры с параметрами VK `vk_app_id` и `vk_user_id` браузерный launcher автоматически выбирает `TargetPlatform.HTML_VK`. Для отдельной VK-сборки можно также задать `GameConfig.TARGET_PLATFORM = TargetPlatform.HTML_VK`.

`html/webapp/index.html` подключает `vk-billing.js`. Скрипт загружает официальный VK Bridge 2.15.0 только при инициализации VK-платформы, отправляет `VKWebAppInit`, проверяет поддержку `VKWebAppShowOrderBox`, обрабатывает отмену и ошибки и возвращает фокус игре.

Сборка: `gradlew.bat html:dist`. Результат: `html/build/dist`; копировать нужно всю папку, включая `vk-billing.js`.

## Сервер

Серверная часть добавлена в `C:/github/mir-server`. Инструкция: `docs/vk-kassa-billing.md` в том репозитории. Сначала обновите сервер, затем клиент.

В настройках платежей приложения VK укажите callback URL:

`https://mir-game.ru/billing_vk_kassa_callback`

На сервере заполните `APP_ID`, `APP_SECRET` и `FULL_VERSION_VOTES` в `src/main/java/com/barbazan/games/mir/server/billing/vk/VKKassaBillingConfig.java`, затем пересоберите и выложите сервер. Переменные окружения для VK не требуются. Защищённый ключ не включается в браузерную сборку. Без этих настроек сервер отклоняет начало оплаты.

Желаемая цена — 299 рублей. В выбранном игровом API стоимость задаётся целым числом голосов VK: перед запуском согласуйте число голосов и задайте его на сервере. Клиент не обещает фиксированную рублёвую цену: итоговую сумму показывает VK.

## Как проходит покупка

1. Клиент просит игровой сервер подготовить заказ (WebSocket action 6). Передаются секрет игрового аккаунта, ID товара и исходные подписанные параметры запуска VK.
2. Сервер проверяет игровой аккаунт и подпись VK, затем подписывает `item`, связывающий товар, цену, игрока kassa и покупателя VK.
3. Клиент открывает `VKWebAppShowOrderBox` с этим `item`.
4. Сервер отвечает VK на `get_item`, а после подписанного `order_status_change` со статусом `chargeable` сохраняет `Purchase`.
5. Уже сохранённая покупка приходит в игру через существующий action 4. Выдача идёт через `billing().consume(product)` и `PurchaseListener`; обработанные токены сохраняются как у остальных биллингов.

Успешное закрытие окна оплаты лишь запускает повторную проверку на сервере. Оно само по себе не выдаёт товар. Покупки восстанавливаются после входа/переподключения и обычной проверкой `restorePurchases()`. Сохраняется существующая модель игровых аккаунтов kassa: доступ к аккаунту определяется его игровым секретом.

## Проверка

- `node --test html/test/vk-billing.test.cjs`
- `gradlew.bat :core:test :html:dist`
- В mir-server: `mvn "-Dtest=VKKassaBillingTest,HibernateVKPurchaseStoreTest" test`

Java-тесты проверяют совместимость платёжных пакетов, повторный вход и восстановление покупки при обрыве связи на любом экране, ранние уведомления, дубликаты и запоздавшие ответы после тайм-аута. Браузерные тесты проверяют загрузку SDK, передачу подписанного товара, отмену, ошибки и повторные попытки.

Для окончательной проверки внутри VK нужны настроенное приложение, callback URL, серверные параметры и реальная или разрешённая тестовая покупка. Автотесты не проводят списания.

Документация: [официальный SDK](https://github.com/VKCOM/vk-bridge), [пример игры VK](https://github.com/VKCOM/vk-direct-games-example), [проверка подписи запуска](https://github.com/VKCOM/vk-apps-launch-params/blob/master/examples/java1.8.java).
