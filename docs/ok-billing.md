# Оплата Одноклассников в kassa

`OKBillingService` подключён через общий `BillingService` и `PurchaseListener`, как оплата ВК. Поддерживается полная версия `full_version`. Платежи ОК и ВК имеют независимые подписанные заказы и токены покупок.

## Запуск и сборка

Одна веб-сборка обслуживает обе площадки. Launcher выбирает `HTML_OK` раньше проверки ВК:

- при `vk_client=ok`;
- при параметрах FAPI `api_server` и `logged_user_id`.

В остальных случаях выбор платформы остаётся прежним. `GameConfig.TARGET_PLATFORM` оставлен `HTML_VK`: условие автоматической выкладки в GitHub не менялось. Для ОК используется тот же адрес `https://mir-game.ru/kassa/`.

`index.html` подключает `ok-billing.js`. SDK Яндекса пропускается внутри обеих площадок. FAPI загружается только в соответствующем запуске ОК. Пакет выкладки обязан содержать оба платёжных скрипта.

## Два варианта запуска ОК

Для запуска с `api_server` используется официальный FAPI: `FAPI.init` и `FAPI.UI.showPayment`, глобальный `API_callback`. Сервер проверяет `auth_sig` и публичный ключ приложения. Цена и защитный `productHash` приходят с сервера. Отмена закрывает попытку без выдачи товара, следующая попытка доступна.

Для запуска с `vk_client=ok` без FAPI-параметров адаптер проверяет поддержку `VKWebAppShowOrderBox` через существующий VK Bridge. Если клиент ОК не поддерживает этот метод, покупка не открывается; инициализацию можно повторить. Сервер подготовлен к отдельным POST-уведомлениям такого режима, но их доступность и формат на реальной площадке ещё требуют проверки.

Важно: таблица совместимости на apiok.ru/apps/vk отмечает этот метод как неподдерживаемый. Переход к единому кабинету разработчика сам по себе не гарантирует оплату через VK Bridge в ОК. Рабочий документированный путь здесь — FAPI; для конкретного приложения нужно проверить фактические параметры запуска и доступные способы оплаты.

## Настройка сервера

В `mir-server` заполните `src/main/java/com/barbazan/games/mir/server/billing/ok/OKKassaBillingConfig.java`:

- `APP_ID`: ID именно приложения ОК, он отличается от ID ВК;
- `APP_PUBLIC_KEY`: публичный ключ ОК для FAPI;
- `APP_SECRET`: защищённый ключ. По умолчанию берётся из конфигурации ВК для общего приложения нового кабинета; у отдельного старого приложения ОК укажите его собственный ключ;
- `FULL_VERSION_OK`: целое число ОК. Пока установлено предварительное значение 299, которое нужно подтвердить перед запуском. Это не обещание цены 299 рублей;
- `ALLOW_TEST_PAYMENTS`: по умолчанию `false`, относится только к условному режиму Bridge.

ID и публичный ключ оставлены пустыми. До их заполнения сервер не разрешает подготовку платежей. Секрет находится только в серверном проекте, в HTML-сборку не попадает. Сервисный ключ не используется.

В поле «URL для платёжных уведомлений Одноклассников» укажите:

`https://mir-game.ru/billing_ok_kassa_callback`

Сначала выложите сервер, затем клиент. Миграция базы не требуется. Подробности серверного протокола: `mir-server/docs/ok-kassa-billing.md`.

## Выдача покупки

WebSocket action 7 проверяет игровой аккаунт и подписанные параметры площадки. Сервер выдаёт заказ, привязанный к покупателю ОК, игровому аккаунту, цене и способу оплаты. Клиент открывает платёжное окно с этим заказом.

Только подписанное уведомление ОК сохраняет покупку в базе. Ответ SDK сам по себе ничего не выдаёт. Покупка приходит через прежний action 4 и восстанавливается после переподключения. Повторные уведомления не создают повторную покупку.

После серверного подтверждения новой покупки показывается существующее окно «Покупка успешна» с кнопкой начала игры. Восстановленная покупка открывает игру без повторного поздравления.

## Проверки

- `node --test html/test/vk-billing.test.cjs html/test/ok-billing.test.cjs`
- `gradlew.bat :core:test :html:dist`
- `node html/test/vk-purchase-flow.browser.cjs` с Playwright и Chromium; при необходимости `PLAYWRIGHT_MODULE` и `BROWSER_PATH`.
- `python scripts/tests/test_web_deploy.py`

Браузерная проверка использует собранный GWT-клиент, подменённые SDK и WebSocket: покупка, раннее серверное подтверждение, восстановление и отмена для ВК/FAPI ОК/условного Bridge ОК. Реальных списаний нет.

Для окончательной проверки нужна страница игры ОК и настройки приложения. Затем проверить реальную оплату, серверное подтверждение, окно успеха и восстановление после перезагрузки.

Источники: [FAPI.showPayment](https://apiok.ru/dev/sdk/js/ui.showPayment/), [callbacks.payment](https://apiok.ru/dev/methods/rest/callbacks/callbacks.payment), [параметры запуска](https://apiok.ru/dev/app/), [совместимость с VK Mini Apps](https://apiok.ru/apps/vk).
